# Сценарий защиты — 3 минуты (WP-C9)

Запуск: `npm run dev` (или ссылка на GitHub Pages). Перед показом нажмите «×20» и дождитесь конца прогрева (в шапке «Модель: в работе»), затем верните «×1». Экран разделён: сверху — **пульт оператора** (мнемосхема, журнал сигналов, карточка), под ним — **тренажёр** с «реальной» трубой. Клавиша T скрывает тренажёр — остаётся чистый пульт; клавиша P — крупный режим для проектора.

## Пресеты

- **Малая утечка 1%** — кнопка «1%» (км ≈ 0,37 L).
- **Большая утечка 10%** — кнопка «10%» (км ≈ 0,8 L).
- **Смена режима без утечки** — «Насос +10%», затем «Задвижка» на 60%.
- **Скрытая утечка** — кнопка «Скрытая» (размер — по ползунку).

## Если жюри спросит

- *«Почему именно N секунд?»* — расстояние до ближайшего датчика давления / скорость волны (~1100 м/с) + время набора статистики при шуме датчиков. На секундомере видны обе величины.
- *«Что при большем шуме?»* — ползунок «Шум датчиков»: порог в долях σ, оценка шума подстраивается сама, время детекции растёт, ложных тревог не прибавляется.
- *«Как выбран порог?»* — стенд подбирает его на прогонах без утечки под 1 ложную тревогу в сутки (по числу тревог при разных порогах), проверка — на других seed.
- *«Насколько можно верить зоне поиска?»* — на полном стенде истинное место внутри зоны в 91–92% случаев; для малых утечек зона широкая, вплоть до всего участка, — так честнее, чем узкий, но неверный отрезок.
- *«Где здесь ML?»* — модель k ближайших соседей, обученная на 240 прогонах симулятора, сужает зону в первые 20 секунд (на 10-й секунде — 7 км вместо 14); дальше физика точнее.
- *«Своя запись?»* — «Запись с датчиков»: любой CSV/Excel, колонки угадываются, детекция на их данных.
