# Гипотезы по детекции (H-B1…H-B9)

Полный прогон стенда 2 ноября 2026: **1195 сценариев × 9 стратегий = 10 755 прогонов**, 15 минут на 3 ядрах (`npm run bench`). Наборы: E3 (900 сценариев: размер 0,5–20% × место 0,1–0,9 L × шум 0,1/0,3/0,5% × нарастание 0/30 с × 5 тестовых seed), E5 (30: насос ±10%, задвижка, сочетания — с утечкой и без), 15 прогонов без утечки по часу (14,8 ч наблюдения), 250 случайных труб. Пороги откалиброваны на **других** seed (валидационных) под 1 ложную тревогу в сутки. Таблицы ниже — `python3 python/analysis/hypotheses.py`, лидерборд — [leaderboard.md](../leaderboard.md), графики — [report.html](../report.html).

## Итог выбора

**Выбрана EWMA (D3)**, `L = 13,2σ`, τ = 3 с: медиана TTD 12,8 с (утечки от 2%), MDL 5%, POD для утечек от 5% — 97%, ложных тревог 0 на 14,8 ч и 0 на сменах режима, ошибка места — медиана 112 м (0,2% длины). CUSUM (D2) по счёту первый, но разница с EWMA статистически незначима (95% интервал разницы счёта включает ноль) — по правилу ТЗ взята более простая. Жёсткие фильтры прошли D1, D2, D3, D6.

**Ни одна тревога не пришла раньше физического предела** (волна до ближайшего датчика) — 0 случаев из всех пойманных.

## Гипотезы

| ID | Гипотеза | Результат | Решение |
| --- | --- | --- | --- |
| H-B1 | CUSUM ловит малые утечки быстрее порога | При равной частоте ложных тревог CUSUM ловит гораздо больше малых утечек: 0,5% — 59% против 25% у порога, 1% — 81% против 37%, 2% — 97% против 75%; время сопоставимо (22 с при 2%) | **Да**: D2 — основа для малых утечек; кандидат слияния EWMA + CUSUM записан в `results/fusion.candidate.json` (шаг 7) |
| H-B2 | Волна давления (D5) — самый быстрый метод для утечек ≥ 5% | Когда срабатывает — ближе всех к физическому пределу (медиана TTD − предел 7,8 с против 9–11 с у остальных), но при шуме 0,1–0,5% шкалы ловит только 28% утечек 5% и 80% утечек 20%; на случайных трубах 13 ложных тревог в сутки | **Частично**: D5 не основной детектор, но L3 (время прихода волны) — первая оценка места |
| H-B3 | Слияние двух лучших быстрее лучшего одиночного на 15% | Слияние CUSUM + D5: медиана TTD 12,4 с против 12,9 с у CUSUM (−4%), но 6 ложных тревог на сменах режима — не прошло фильтр | **Нет**: лучший одиночный; слияние без D5 — кандидат для следующего прогона |
| H-B4 | Сигнатурный фильтр убирает ≥ 95% ложных тревог от режима, добавляет ≤ 0,5 с | Нестационарный twin + защита от переходного режима + сигнатура: 0 ложных тревог у D1–D4, D6, D9 на всех E5 без утечки. Утечка 5% через 10 с после смены режима: CUSUM — 5,8 с, EWMA — 9,1 с (порог в это время ×1,5). Без защиты и с подавлением по сигнатуре утечки на фоне режима пропускались — исправлено | **Да**: фильтр и защита по умолчанию |
| H-B5 | Детектор без физики отстаёт от лучшего физического не больше чем вдвое | D8 (RLS) по времени даже быстрее (медиана 10 с), но 50 ложных тревог в сутки по всем прогонам, 4 — на сменах режима, на случайных трубах — 266/сут; D9 (PCA) — хуже по обоим | **Нет** как самостоятельная стратегия: D8/D9 — запасной путь только при постоянном режиме и без параметров трубы |
| H-B6 | Пороги в σ переносятся между трубами: ложных не больше 3× цели | Пороги откалиброваны на трубе по умолчанию; на 250 случайных трубах (5–200 км, Ø0,2–1,2 м, 3–10 датчиков, шум до 1%) у D1–D4, D6 — 0 ложных тревог. Доля пойманных на случайных трубах ниже (CUSUM 73%: длинные трубы, редкие датчики, шум до 1%) | **Да** по ложным тревогам; для чужой трубы `autotune` всё равно рекомендуется (снижает порог, если шум меньше) |
| H-B7 | L2 точнее L1 и L3: ошибка < 2% длины при 5 датчиках | Связка «L3 сразу, L2 после затухания волн, объединение по ширине интервала»: медиана ошибки 105–113 м (0,2% длины) по всем пойманным в E3. По отдельности: для утечек 5% L3 ошибается на 0,1–0,5 км сразу; L2 до затухания волн (~1,5 пробега) не годится, после — 1–2 км при двух внутренних датчиках; L1 — хуже (зависит от точности расходомеров). D6 (Калман) — 3,1 км | **Да, в связке**: L3 → L2 по умолчанию. Отдельный E7 — `npm run bench -- --strategies configs/strategies/e7-localization.json --suite e3` (в этот прогон не входил) |
| H-B8 | Минимальная обнаружимая утечка падает как 1/√(число датчиков) | Не проверено: E4 не входил в полный прогон | Запустить `npm run bench -- --reuse-tuned --suite e4 --out results/runs.e4.csv` |
| H-B9 | Наложение утечки на реальный шум оценивает время детекции не хуже 20% | На одном прогоне (утечка 5%, запись в «чужом» формате): совпадение в пределах 20% (T-B16). На 50 записях не проверялось — реальных записей пока нет | **Да** предварительно: инструмент готов (`overlayLeaks` в сценарии) |
