# @pipetwin/web — демо-интерфейс

Vite + TypeScript без фреймворка, Canvas 2D (схема) и uPlot (графики). ТЗ, WP-C4…C6, C8, C9.

```bash
npm run dev        # http://localhost:5173
npm run build      # статическая сборка apps/web/dist — работает без бэкенда и офлайн
```

## Архитектура (WP-C5)

```
воркер симуляции (plant, датчики, правда)  ──кадры──▶  основной поток  ──только кадры──▶  воркер детектора (свой twin + стратегия)
                                                 ◀── профиль, утечки (для секундомера и маркера)        ◀── прогноз, выход, карточки
```

- `src/engine/sim-engine.ts`, `detect-engine.ts` — логика воркеров без API браузера (тестируется в Node, `test/engine.test.ts`).
- Модельное время — свой таймер воркера симуляции; графики обновляются не чаще 30 раз/с.
- События сессии (утечки, режим, отказы) записываются во времени plant → «Сценарий для стенда» воспроизводит ту же тревогу в то же модельное время (T-C11, T-C15).

## Что на экране

Экран разделён на две части, как на учебном тренажёре диспетчера: **пульт оператора СОУ** (только то, что знает система обнаружения утечек) и **панель тренажёра** (правда симулятора и управление; выделена янтарной штриховкой, скрывается клавишей T или кнопкой «Тренажёр» в шапке). Стиль — спокойная графитовая палитра по ISA-101: цвет только для отклонений (жёлтый), аварий (красный) и информации (голубой).

### Пульт оператора

| Блок | Что |
| --- | --- |
| Шапка | Участок, состояние подсистем: СОУ (норма / подозрение / авария), связь (идут ли кадры), модель (прогрев / в работе), режим перекачки (стационарный / переходный), датчики (исправных из всех), детектор; модельные часы |
| Строка аварии | Самый важный неквитированный сигнал: «АВАРИЯ · время · признаки утечки: зона поиска км A–B (по волне давления), ≈ N м³/ч» и кнопка «Квитировать». Неквитированная авария мигает |
| Мнемосхема | Станции на концах (НПС, КП), труба с направлением потока, таблички датчиков с текущими значениями (жёлтая рамка — отклонение от модели, красная — неисправен, ▸М — вход модели), **зона поиска утечки** с подписью стадии и ромб оценки места, строка состояния |
| Сужение зоны поиска | «Воронка» после тревоги: по горизонтали — километраж, по вертикали — секунды после тревоги; цвет — стадия оценки (первый датчик → ML → волна → профиль) |
| Журнал сигналов | Приоритет (авария / предупреждение / инфо), время, источник и сообщение, состояние (активен / квитирован / снят), квитирование по одному и всех, выгрузка CSV |
| Карточка события | Тип, уверенность, **зона поиска (≈90%)** и как она определена, расход, потери к тревоге и прогноз за 30 мин, вклад датчиков, рекомендация из `configs/actions.json`, «Принять», история, экспорт JSON |
| Тренды | Давление и расход: замер и прогноз модели; статистика детектора и порог; нормированные невязки z; метки «утечка» и «тревога» |
| Датчики | Тег, километр, значение, состояние (вход модели / норма / отклонение z / неисправен) |
| Системный журнал | События сессии; под катом — что именно получает детектор (граница честности) |
| Параметры трубы | Статусы given / default / calibrated, «Откалибровать», форма из JSON Schema, паспорт текстом, загрузка конфига |

### Тренажёр (инструктор)

| Блок | Что |
| --- | --- |
| Реальная труба | Правда симулятора: профиль высот, труба в цвете давления, истинная утечка ▲ и оценка системы ▼; клик по трубе ставит утечку; наведение — p, Q, T в точке |
| Секундомер | «Обнаружено за X с», физический минимум для места утечки, ошибка оценки места; слепой режим — без подсказок |
| Управление | Размер и нарастание утечки, место в км, пресеты 1/5/10%, скрытая утечка, список утечек с удалением, насос ±5/±10%, задвижка, шум, отказ любого датчика, скорость ×1/×5/×20, пауза, перезапуск, новый seed, ошибка модели вкл/выкл |
| Стратегия | По умолчанию — `configs/strategy.selected.json`; любой детектор реестра |
| Запись (replay) | Мастер импорта CSV / Excel (.xlsx) / JSON; шкала записи с перемоткой |
| Экспорт | Сценарий для стенда, журнал CSV, графики PNG |
| Презентация | Клавиша P: схема и тренды на всю ширину |

## Гипотезы H-C1…H-C6

| ID | Гипотеза | Результат | Решение |
| --- | --- | --- | --- |
| H-C1 | Canvas 2D хватает, WebGL не нужен | Headless Chromium без GPU, 1600×1100, ×20: 43 кадра/с (пустая страница — 60). Профиль CPU: JavaScript интерфейса < 10% времени, остальное — программная растеризация canvas. Перерисовка — только при новых данных, схема — только при изменении | WebGL не делаем; на машине с GPU запас больше |
| H-C2 | `postMessage` хватает при 30 обновлениях/с | Кадры и профили передаются структурным клонированием пакетами раз в 50 мс; задержек в демо нет. Отдельно на 5000 узлах не мерили | `SharedArrayBuffer` не нужен (и не требует особых заголовков хостинга) |
| H-C3 | Браузер разбирает CSV 100 МБ < 10 с | В Node разбор 100 МБ — 5,7 с (T-C05); в браузере разбор идёт в отдельном воркере с прогрессом | Импорт целиком в браузере; `/datasets` API — для .parquet/.h5 |
| H-C4 | Автоугадывание сокращает подключение файла до 10 мин | На 5 образцах угадано ≥ 80% колонок (T-C06), на выгрузке с тэгами КИП — 100% без вопросов | Мастер — основной путь |
| H-C5 | Replay в браузере и стенд в Node дают одинаковые тревоги | Один код движков; экспорт сессии → стенд: расхождение < 0,1 с (T-C11, T-C15) | Демо подкрепляем цифрами стенда |
| H-C6 | Человек со стороны понимает демо за 30 с | Не проверялось на людях | Проверить на 2–3 людях до защиты |
