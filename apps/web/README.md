# @pipetwin/web — демо-интерфейс

Vite + TypeScript без фреймворка, Canvas 2D (схема) и uPlot (графики). ТЗ, WP-C4…C6, C8, C9.

```bash
npm run dev        # http://localhost:5173
npm run build      # статическая сборка apps/web/dist — работает без бэкенда и офлайн
```

## Архитектура (WP-C5)

```
воркер симуляции (plant, датчики, правда)  ──кадры──▶  основной поток  ──только кадры──▶  воркер детектора (свой twin + стратегия)
                                                 ◀── профиль, утечки (для секундомера и маркера)        ◀── прогноз, выход, карточки
```

- `src/engine/sim-engine.ts`, `detect-engine.ts` — логика воркеров без API браузера (тестируется в Node, `test/engine.test.ts`).
- Модельное время — свой таймер воркера симуляции; графики обновляются не чаще 30 раз/с.
- События сессии (утечки, режим, отказы) записываются во времени plant → «Сценарий для стенда» воспроизводит ту же тревогу в то же модельное время (T-C11, T-C15).

## Что на экране

| Блок | Что |
| --- | --- |
| Секундомер | «Обнаружено за X с», физический минимум для места утечки, ошибка оценки места; слепой режим — без подсказок |
| Схема | Профиль высот, труба в цвете давления (plant в симуляции, twin в replay), датчики из конфига (неисправные — красным), истинная утечка ▲, оценка ▼ с интервалом; клик — утечка; наведение — p, Q, T в точке |
| Графики | Давление и расход: замер и прогноз twin; статистика детектора, действующий порог и полоса тревоги; нормированная невязка z |
| Управление | Размер и нарастание утечки, пресеты 1/5/10%, скрытая утечка, насос ±5/±10%, задвижка, шум, отказ любого датчика (скачок, дрейф, залипание, нет данных, выброс), скорость ×1/×5/×20, пауза, перезапуск, новый seed, ошибка модели вкл/выкл |
| Стратегия | По умолчанию — `configs/strategy.selected.json` (с цифрами стенда); любой детектор реестра (неподходящие к датчикам недоступны с причиной) |
| Карточка события | Тип, уверенность, место ± ошибка, расход, потери и прогноз за 30 мин, вклад датчиков, рекомендация из `configs/actions.json`, «Принять», история, экспорт JSON |
| Журнал | Сообщения, которые получает детектор (доказательство честности), и события сессии |
| Параметры трубы | Статусы given / default / calibrated, «Откалибровать», форма из JSON Schema, паспорт текстом, загрузка конфига |
| Запись (replay) | Мастер: файл разбирается в воркере, колонки угадываются, можно поправить и сохранить профиль |
| Экспорт | Сценарий для стенда, журнал CSV, графики PNG |
| Датчики | Последнее значение, нормированная невязка z, роль (граница twin), неисправность |
| Шкала записи | В режиме replay: позиция и перемотка (детектор после неё начинает с прогрева) |
| Презентация | Кнопка в шапке или клавиша P: крупный секундомер и схема на всю ширину, без боковых панелей |
| Метки на графиках | Вертикальные линии «утечка» (красная) и «тревога» (оранжевая) — задержку видно глазами |

## Гипотезы H-C1…H-C6

| ID | Гипотеза | Результат | Решение |
| --- | --- | --- | --- |
| H-C1 | Canvas 2D хватает, WebGL не нужен | Схема перерисовывается целиком на каждый кадр (≤ 400 цветных отрезков) без заметной нагрузки на 500 узлах при ×20 | WebGL не делаем |
| H-C2 | `postMessage` хватает при 30 обновлениях/с | Кадры и профили передаются структурным клонированием пакетами раз в 50 мс; задержек в демо нет. Отдельно на 5000 узлах не мерили | `SharedArrayBuffer` не нужен (и не требует особых заголовков хостинга) |
| H-C3 | Браузер разбирает CSV 100 МБ < 10 с | В Node разбор 100 МБ — 5,7 с (T-C05); в браузере разбор идёт в отдельном воркере с прогрессом | Импорт целиком в браузере; `/datasets` API — для .parquet/.h5 |
| H-C4 | Автоугадывание сокращает подключение файла до 10 мин | На 5 образцах угадано ≥ 80% колонок (T-C06), на выгрузке с тэгами КИП — 100% без вопросов | Мастер — основной путь |
| H-C5 | Replay в браузере и стенд в Node дают одинаковые тревоги | Один код движков; экспорт сессии → стенд: расхождение < 0,1 с (T-C11, T-C15) | Демо подкрепляем цифрами стенда |
| H-C6 | Человек со стороны понимает демо за 30 с | Не проверялось на людях | Проверить на 2–3 людях до защиты |
